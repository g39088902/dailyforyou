# 前端侧契约（frontend）

> 你不持有"系统里有哪些媒体"这份知识。你只持有"这个用户想看哪些、按什么顺序"。
> 清单和图标都由后端下发，你负责渲染、合并和降级。

---

## 0. 产品设计（PRD）

> 本节讲用户看到什么、为什么是这些数字，第 1 节之后讲删改清单与代码位置。

### 0.1 这个模块的产品角色

前端是唯一被用户直接看见的一层。它要把 43 个源的杂乱更新，压成**一条可以三分钟扫完的流**，并且让「不同意 AI」这件事只需要一次拖动。

| 承诺 | 表现形式 | 违约时 |
| :--- | :--- | :--- |
| 打开即读 | 第一个源返回就渲染，其余追加 | 转圈十秒，用户直接关掉 |
| 顺序可解释 | 分数降序 + 色阶 + 一句理由 | 用户不知道为什么这条在第一 |
| 判断可覆盖 | 悬浮拖拽改分，松手重排 | 用户只能接受一套不属于自己的排序 |
| 读完即清空 | 已读沉底、可一键隐藏 | 每天重新面对同一批旧内容 |

### 0.2 服务对象与场景

| 角色 | 场景 | 他要什么 |
| :--- | :--- | :--- |
| 读者（主要） | 早上通勤 3 分钟、午休补一次、晚上清空 | 快速判断「今天有没有值得读的」 |
| 读者（设置态） | 第一次用，或口味变了 | 关掉不关心的频道、调整顺序 |
| 维护者（自己） | 改规则 | 一个能直接编辑并试跑的 Prompt 输入框 |

### 0.3 用户故事

| 编号 | 故事 | 验收 |
| :--- | :--- | :--- |
| F-01 | 我打开首页，第一批内容应该马上出现 | 第 1 个源返回即渲染，首条可见 P75 < 1.5s |
| F-02 | 我一眼看出哪条最值得读 | 分数降序 + L1–L5 色阶 + 25 字理由 |
| F-03 | 我觉得某条被高估 / 低估，能立刻改 | hover 出手柄，拖动预览，松手提交并重排 |
| F-04 | 我读过的内容不要在我眼前消失 | 本次会话新读条目不隐藏，下次进入才沉底 |
| F-05 | 我只想保留 5 个频道 | 设置里开关 + 拖拽排序，刷新后保持 |
| F-06 | 我在手机上也能读 | 360px 宽无横向滚动，可加到桌面 |
| F-07 | 后端挂了我不该看到白屏 | 有快照用快照并提示；无快照显示「正在初始化」 |
| F-08 | 我要知道这个分是谁给的 | tooltip 区分「AI 实时 / 缓存 / 我改过」 |

### 0.4 信息架构

| 路由 | 页面 | 一句话 | 地位 |
| :--- | :--- | :--- | :--- |
| `/` | Stream 聚合流 | 默认入口，所有频道的合并视图 | 主 |
| `/list` | 单源看板 | 「我就想看某一个源」的退路 | 辅 |
| `/setting` | 全局设置 | 主题、字号、跳转方式、频道开关与排序 | 辅 |
| `/account` | 账户与 Prompt | 登录、地址、规则编辑与试跑 | 辅 |
| `/403` `/404` `/500` | 错误页 | 说清楚发生了什么 | 兜底 |

Stream 与 List 不是平级的：Stream 回答「今天读什么」，List 回答「这个源现在有什么」。

### 0.5 交互规则（带数字的部分是契约）

| 规则 | 取值 | 为什么 |
| :--- | :--- | :--- |
| 首屏加载 | 按设置顺序串行请求，第 1 个源返回即渲染 | 27 个源并发会挤占带宽，先给一条能读的 |
| 排序 | 已评分按分数降序，未评分按原顺序排在其后 | 不给未评分的条目编造位置 |
| 色阶 | ≥90 L1 / ≥75 L2 / ≥60 L4（L3 与 L4 共用区间）/ ≥40 Uncertain / <40 L5 | 颜色只表达层级，精确值看数字 |
| 改分 | 拖动实时预览，松手提交；失败回滚并提示 | 不允许「看起来改了其实没改」 |
| 已读 | 元素 50% 进入视口并停留 450ms | 已读是「看了一眼」，不是「点过链接」 |
| 沉底 | 本次新读的条目不立即隐藏 | 列表不能在鼠标底下跳动 |
| 隐藏已读 | 头部常驻开关，旁边显示已读条数 | 清空动作要一步可达 |
| 进度可见 | 「信源加载 12/27」「AI 评分中 40/120 · 并发 5/5」 | 等待可解释，就不算卡 |
| 登录门槛 | 未登录可读、不可评分 | 先让人读到价值，再要求登录 |

### 0.6 状态与文案

| 状态 | 界面 | 文案 |
| :--- | :--- | :--- |
| 首屏加载 | 骨架屏 + 进度 | 「正在优先请求第 1 个信源（财联社），获取后立即呈现在列表…」 |
| 部分加载 | 已到的先渲染，底部进度条 | 「已加载 12/27 个信源 · 已评分 40/120 条」 |
| 无数据 | 空态 + 前往设置 | 「暂无热点资讯或所有信源已在设置中关闭」 |
| 全部已读 | 空态 + 恢复按钮 | 「全部 120 条内容均已阅读过并被隐藏」 |
| 清单初始化 | 空态 + 重试 | 「正在初始化，请稍后重试」 |
| 清单降级 | 顶部提示条 | 「清单可能不是最新」，后台静默重试 |
| 信源 404 | 移除该频道 + toast | 「信源已下线」 |
| 信源 `enabled: false` | 灰显不可点 | hover：「该信源暂不可用」 |
| 未登录 | 头部常驻标签 | 「登录后启用 AI 评分」 |
| 单条评分失败 | 该条保持未评分 | 不阻塞其他条目，不弹窗 |

文案的共同标准：**说事实，不说「出错了」。** 「正在初始化」和「加载失败」是两种完全不同的处境，不能共用一句话。

### 0.7 成功指标

| 指标 | 定义 | 目标 |
| :--- | :--- | :--- |
| 首条可见时间 | 打开到第一条内容渲染 P75 | < 1.5s |
| 全量加载时间 | 27 个源 × 30 条完成 P75 | < 8s |
| 改分成功率 | 提交成功且重排正确的比例 | ≥ 99% |
| 重排延迟 | 松手到列表重排 | < 100ms |
| 已读误标率 | 用户认为「我没看过」的已读条目占比 | < 2% |
| 空态误报 | 有数据却显示空态的次数 | 0 |
| 设置持久化 | 刷新 / 换页后设置保持 | 100% |

### 0.8 不做什么

- **不做无限滚动。** 27 × 30 已经 800 多条，一天读不完；分页会把「扫一遍」变成「刷下去」。
- **不做评论、点赞、分享。** 这是阅读器，不是社区。
- **不做内置正文阅读器。** 点击即跳源站，尊重原作者与流量。
- **不做多画像 Tab。** 在 Roadmap 里，等单套规则被用顺了再说。
- **不内置兜底清单。** 见第 5 节：内置一份就又是一份会漂移的真相。

## 1. 边界

| 项 | 内容 |
| :--- | :--- |
| 拥有 | 用户偏好（开关、排序）、上次成功的清单快照、已读集合 |
| 依赖 | `GET /sources` 拿清单，`GET /{name}?type={subType}` 拿列表，`GET /logo/{key}.png` 拿图标 |
| 不知道 | 爬虫、数据库、`source_name` / `sub_type` 的存储细节 |
| 禁止 | 在 `src` 里写死任何媒体名、路径前缀规则、图标文件名 |

## 2. 要删掉的东西

这次改造的主体是**减法**。四个位置、四份清单，全部交给 `/sources`：

| 文件 | 删除内容 | 替代 |
| :--- | :--- | :--- |
| `src/store/index.js` | `defaultNewsArr`（27 个频道）、`newsArr`、`checkNewsUpdate` 的 merge 逻辑 | `/sources` 响应 |
| `src/api/index.js` | `getHotLists` 的 `cls-` / `jiemian-` / `reuters-` / `jin10-` / `bloomberg-` 五个前缀白名单 | 清单里的 `name` + `params` |
| `src/components/Stream/StreamSourceNav.vue` | `@error` 静默隐藏图标的逻辑 | 后端保证永不 404 |
| `public/logo/` | 32 张 png | `GET /logo/{key}.png` |

`getHotLists` 那一处现在最容易出事：它把 `jiemian-hot` 映射成 `/jiemian`、`reuters-world` 映射成 `/reuters`，靠字符串前缀猜测。**新增一个带子类型的信源（比如 `ft-markets`）时，如果不改这里，请求直接 404。** 改成读清单里的 `name` + `params` 之后，这个问题从根上消失。

`checkNewsUpdate` 的 merge 逻辑（保留用户 `show`/`order`，用新默认值覆盖 `label`/`params`，补新增、删下线）本质是"手工模拟一次服务端下发"。现在有真的下发了，这套逻辑可以整段删除。

## 3. 请求拼装

```js
// 列表
const src = sources.find(s => s.key === key);
await api.get(`/${src.name}`, { params: { ...src.params, limit: 30 } });
// → GET /reuters?type=world&limit=30

// 图标（相对路径，需拼 baseURL）
const src_url = `${FEED_BASE_URL}${src.logo}`;
```

`src.params` 直接展开，不做任何字符串变形。`src.key` 只用于 React/Vue 的 key、`localStorage` 和已读集合，**不参与 URL 拼接**。

图片统一写成：

```html
<img :src="FEED_BASE_URL + source.logo" :alt="source.label" />
```

**不要加 `@error` 隐藏**。后端三级 fallback 保证任何源都有图，`@error` 只会掩盖真正的问题。

## 4. 状态模型

```js
// 持久化：只有个人偏好 + 上次成功的清单快照
{
  "sourcePrefs":     { "reuters-world": { "show": true, "order": 20 } },
  "sourcesSnapshot": { "etag": "src-8f3a1c", "sources": [ /* ... */ ] }
}

// 内存：运行时合并
sources = snapshot.sources
  .map(s => ({ ...s, show: prefs[s.key]?.show ?? s.defaultOn, order: prefs[s.key]?.order ?? s.order }))
  .sort((a, b) => a.order - b.order);
```

`key` 就是现在 UI 里的 `jiemian-hot`，所以**老用户的 `localStorage` 无需迁移**——这一点在改字段名时最容易破坏，务必保留。

`localStorage` 键名建议：`sourcePrefs`、`sourcesSnapshot`（与现状的 `newsArr` 分开，避免读到旧结构）。

## 5. 降级策略（两级）

| 情况 | 行为 |
| :--- | :--- |
| `/sources` 正常 | 用响应，覆盖 snapshot |
| `/sources` 失败，有 snapshot | 用 snapshot，后台指数退避重试，顶部提示"清单可能不是最新" |
| `/sources` 失败，无 snapshot（首次访问即断网 / 后端全挂） | 空态页："正在初始化，请稍后重试" + 重试按钮 |

**刻意不给前端内置兜底清单。** 一旦内置，就又是一份会漂移的真相——这正是这次要消灭的东西。首次断网的极端场景用空态页接住，代价明确、可接受。

另外要处理 `initialized: false`：后端返回了 200 但表是空的（新环境刚部署）。此时也走空态页，但文案是"正在初始化"，而不是"加载失败"。

## 6. 错误处理

后端改了错误语义（详见 [`backend.md`](./backend.md) 第 6 节），前端要跟上：

| 场景 | 前端行为 |
| :--- | :--- |
| `404 unknown source` | 该频道显示"信源已下线"，并**把它从本地列表移除**——这通常是清单里残留了后端不认识的名字 |
| `200 + data: []` | 正常空态："暂无数据" |
| `stats.stale: true` | 频道标题旁加"数据可能滞后"标记（P2，可先只记日志） |
| `enabled: false` | 频道灰显，不可点击，hover 提示"该信源暂不可用" |
| `/sources` 返回 `initialized: false` | 空态页，文案"正在初始化" |

`404` 从"静默空频道"变成明确的错误信号，这是这次改造最直接的收益之一。

## 8. 禁止事项

1. **不要在代码里写任何媒体名**。包括数组、对象键、`if (name === "reuters")`、常量文件。
2. **不要写路径前缀规则**。`name` 和 `params` 从清单来，不需要你推断。
3. **不要兜底一份内置清单**，哪怕是"只有几个常见的"。
4. **不要手拼 `/logo/{name}.png`**，一律用后端给的 `source.logo`。
5. **不要静默吞掉 404**。它是唯一能告诉你"清单与后端不一致"的信号。
